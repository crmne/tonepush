TonePush 0.6.1 keeps the editor responsive on Wayland when the compositor stops showing its window, draws frames in step with the display, and is the first release whose Mac app is signed and notarized by Apple, so it opens with a double-click and installs through Homebrew.

## Fixed

- **The editor no longer freezes on Wayland when its window is out of sight.** Hyprland and other compositors stop drawing a window that is covered by a fullscreen or maximized one, sits on a hidden workspace, or is on a display that has gone to sleep. TonePush now stops painting while it is hidden instead of waiting for a frame that never comes, so the compositor no longer reports it as not responding. The connection to the pedal, changes to your tone library, and update checks keep being handled in the meantime. By @crmne; thanks @fgrehm, whose ZapFast report (crmne/zapfast#190) led to the fix now shared by TonePush, ZapFast, and Spotifast. (emilk/egui#8631, rust-windowing/winit#4709)
- **Frames follow the display's refresh on every platform.** 0.6.0 turned vsync off everywhere to avoid the freeze above, so every mouse movement drew a new frame as fast as the machine could. The editor now waits for the display again on macOS, Windows, X11, and Wayland. By @crmne.

## New

- **The Mac app is signed and notarized.** The DMG opens like any other Mac app, without the trip through **System Settings → Privacy & Security** that earlier versions needed, and the command-line tools in the Mac archive are notarized too. By @crmne.
- **Install with Homebrew:** `brew install --cask crmne/tap/tonepush` for the app, or `brew install crmne/tap/tonepush` for the `tonepush` and `tonepush-gui` binaries. By @crmne.
- **A ready-made Arch package:** `yay -S tonepush-bin` installs the released build with its udev rule and desktop entry. `tonepush` builds the release from source and `tonepush-git` the latest commit. By @crmne.

## Known limitations

- Downloads of 0.6.0 and earlier stay unnotarized; only this release and later open without the Privacy & Security step.
- These reports remain open and are not addressed here: an HX Stomp on firmware 3.80 that stays on "transferring data" (#5), `tonepush set` being unable to write enum parameters (#7), and parser and labelling problems on the HX Effects with firmware 3.80 (#9).
